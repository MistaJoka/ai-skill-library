# How to use: Visual Design

## When to use
Use when an interface is difficult to scan, visually inconsistent, or needs a deliberate visual polish pass.

## How to invoke
Ask your agent: "Read `skills/visual-design/SKILL.md` and apply it to [specific view or flow]. Preserve existing functionality, use the current stack, and report changes and checks."

## Expected results
A documented design rationale and focused UI changes with consistent tokens, responsive layouts, clear hierarchy, and before/after evidence.

## Where it does not do well
Cannot infer a brand from nothing, replace user research, or guarantee conversion improvements. Not appropriate for backend-only tasks or when existing brand constraints are unknown.

## Prerequisites
Access to project files and clear target behavior; screenshots/browser tools are needed for visual verification claims.

## Acceptance check
Confirm the requested view or interaction works as before, improvements are inspectable, accessibility constraints are preserved, and all unverified checks are labeled.
